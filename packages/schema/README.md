# phzyx-schema (monorepo internal)

Phzyx schema language — Pydantic models → Manifest IR → CREATE TABLE (Postgres / SQLite).

**Not a separate PyPI project.** Install the product:

```bash
uv add 'phzyx-forge[sqlite]==0.1.0'
# import: from phzyx.schema …
```

## Quick start

```python
from phzyx.schema import Dialect, Field, Model, build_manifest, render_manifest_ddl

class User(Model):
    id: int = Field(primary_key=True)
    email: str = Field(unique=True, index=True)

    class Meta:
        table = "users"

manifest = build_manifest([User])
print(render_manifest_ddl(manifest, Dialect.SQLITE)[0])
# → "id" INTEGER PRIMARY KEY  (identity / rowid)
```

Full walkthrough: [docs/define-your-first-model.md](../../docs/define-your-first-model.md).

### Primary keys

Single int PK defaults to dialect identity (`INTEGER PRIMARY KEY` /
`GENERATED BY DEFAULT AS IDENTITY` / `AUTO_INCREMENT`). Opt out with
`autoincrement=False`. Timestamps: `auto_now_add` / `auto_now`.

## Field metadata

`Field(...)` stores DB keys under `json_schema_extra["phzyx"]` (`ColumnMeta`):

`primary_key`, `unique`, `index`, `foreign_key`, `on_delete`, `server_default`, `db_type`,
`renamed_from`, admin hints, `file_kind`, `autoincrement`, `auto_now_add`, `auto_now`.

## Model & registry

- Concrete models build `__phzyx_table__` and require **≥1 PK** (composite supported).
- Auto-register on the default registry (`get_registry()`); opt out with `Meta.register = False`.
- `Meta.primary_key = ("a", "b")` alternative to multi-field `primary_key=True`.

## Manifest

`build_manifest(models)` → `Manifest` with `manifest_version = 1`. JSON helpers:
`manifest_to_json` / `manifest_from_json`.

## DDL (create-only)

- `render_create_table` / `render_manifest_ddl` for `postgres` and `sqlite`
- `apply_sql` / `apply_manifest_sqlite` for thin execution

Schema **diff / push / migrate** arrives in M2 (`phzyx-engine`).
